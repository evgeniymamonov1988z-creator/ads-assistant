# Рекламный ассистент (Яндекс Директ API v5 + Google Ads API)

Веб-приложение: собирает статистику кампаний, считает CPA/CTR/расход, сравнивает с вашими целевыми KPI,
находит аномалии и предлагает изменения. **Любая правка уходит в рекламный кабинет только после нажатия
«Подтвердить»** — без подтверждения ни один запрос-мутация не отправляется.

---

## 1. Что внутри

```
adassistant/
├── backend/                  FastAPI (Python 3.10+)
│   ├── app/
│   │   ├── main.py           приложение, раздача собранного фронтенда, проверка ключа доступа
│   │   ├── config.py         все секреты — только из переменных окружения
│   │   ├── models.py         модели данных (метрики, рекомендации, журнал)
│   │   ├── storage.py        настройки KPI + журнал (JSON/JSONL на диске)
│   │   ├── api/routes.py     REST: анализ, подтверждение, журнал, настройки
│   │   ├── core/metrics.py   CTR, CPC, CPA, среднесуточный расход
│   │   ├── core/rules.py     правила анализа и генерация рекомендаций
│   │   ├── core/engine.py    сбор данных из всех кабинетов за 7 дней и последний день
│   │   └── providers/        yandex.py, google.py, mock.py (демо), http.py (лимиты/повторы)
│   ├── static/               собранный фронтенд (уже готовый)
│   ├── requirements.txt
│   └── .env.example
└── frontend/                 React + TypeScript + Vite (исходники)
```

## 2. Быстрый старт (без реальных ключей)

```bash
cd backend
python -m venv .venv && source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt
MOCK_MODE=1 uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Откройте http://127.0.0.1:8000 — интерфейс с демо-данными (5 кампаний, видно аномалии и рекомендации).
Демо-режим (`MOCK_MODE=1`) **никогда** не обращается к реальным API.

Windows (PowerShell):
```powershell
cd backend
python -m venv .venv; .\.venv\Scripts\activate
pip install -r requirements.txt
$env:MOCK_MODE="1"; uvicorn app.main:app --host 127.0.0.1 --port 8000
```

## 3. Подключение реальных кабинетов

1. Скопируйте `backend/.env.example` в `backend/.env` и заполните.
2. Загрузите переменные (или задайте в панели хостинга / systemd / Docker).

### Яндекс Директ API v5
| Переменная | Что это |
|---|---|
| `YANDEX_OAUTH_TOKEN` | OAuth-токен Директа (получается по ссылке из oauth.yandex.ru с правами `direct:api`) |
| `YANDEX_AGENCY_CLIENT_LOGIN` | логин клиента, если работаете через агентский аккаунт (иначе пусто) |

Токен привязан к конкретному рекламному аккаунту Яндекса; для агентства — ещё и логин клиента.

### Google Ads API
| Переменная | Что это |
|---|---|
| `GOOGLE_ADS_DEVELOPER_TOKEN` | из Google Ads → API Center (строка обязательна всегда) |
| `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` | OAuth-клиент проекта Google Cloud |
| `GOOGLE_REFRESH_TOKEN` | refresh token пользователя, у которого есть доступ к рекламе |
| `GOOGLE_LOGIN_CUSTOMER_ID` | MCC без дефисов, если доступ через управляющий аккаунт |
| `GOOGLE_CUSTOMER_ID` | идентификатор рекламного аккаунта без дефисов |
| `GOOGLE_ADS_API_VERSION` | по умолчанию `v19` |

> **Важно про уровень доступа.** С developer token в статусе «тест» Google отвечает ошибкой
> `DEVELOPER_TOKEN_NOT_APPROVED` — работают только тестовые аккаунты. Для реального аккаунта нужен Basic access.
> Приложение переводит это в понятное сообщение и не теряет данные: анализ продолжается по Яндексу.

### Про ключ доступа
Если задать `API_KEY`, все запросы-изменения (POST/PUT) требуют заголовок `X-API-Key`. Интерфейс
спросит ключ и запомнит его в браузере. Рекомендуется включать, если приложение доступно не только с localhost.

**Секреты храните только в переменных окружения / `.env`. `.env` не коммитьте.**

## 4. Как работает режим «анализ и предложения»

1. Кнопка «Проанализировать» → `POST /api/analyze`.
2. Сервер берёт **последний полный день** (`сегодня − 1`) и **7 дней** до него, отдельными запросами —
   чтобы видеть «вчера» отдельно от недельного среднего.
3. Считает по каждой кампании: показы, клики, расход, конверсии, CTR, CPC, CPA, среднесуточный расход.
4. Сравнивает с вашими KPI из «Настроек» и формирует аномалии и рекомендации:

| Правило | Что предлагается | Приоритет |
|---|---|---|
| Перерасход: расход вчера > дневной бюджет × (1 + допуск) | снизить дневной бюджет (не ниже 50%) | высокий |
| CTR за 7 дней < цель × (1 − допуск по CTR) | минус-слова из поисковых запросов без конверсий | средний/высокий |
| CPA за 7 дней > цель × (1 + допуск), кликов хватает | снизить ставки на `N%` (по умолчанию 15%) | средний/высокий |
| Расход есть, конверсий нет | ограничить нецелевой трафик (минус-слова) | высокий |
| Израсходовано < 30% бюджета | предупреждение «кампания недоливает» | — |

5. Для каждой рекомендации показывается **превью**: что меняем (ставка / бюджет / минус-слова), было → станет.
6. «Подтвердить и применить» → `POST /api/recommendations/{id}/confirm` с именем подтверждающего.
   Только теперь вызываются методы API (`keywords.setBids`, `campaigns.update`, `adgroups.update` для Яндекса;
   `googleAds:mutate` для Google).
7. Подтвердить можно только свежую рекомендацию из последнего анализа. После перезапуска сервера
   или нового анализа старое предложение честно отвечает: «данные обновились, запустите анализ заново».

## 5. Журнал действий

`GET /api/journal`, в интерфейсе — раздел «Журнал», выгрузка — `GET /api/journal.csv` (открывается в Excel).

Запись содержит: дату, кампанию, источник, тип действия, статус (**предложено / подтверждено / ошибка / отклонено**),
кто подтвердил, что именно изменено (было → стало) и результат. Журнал ведётся на диске (`data/journal.jsonl`),
поэтому не теряется при перезапуске.

## 6. Лимиты API и ошибки

- Запросы идут с таймаутами; на 429/5xx — до 2 повторов с паузой (учитывается заголовок `Retry-After`).
- Все ошибки переводятся на русский: истёк токен, нет прав на аккаунт, исчерпана квота, лимит баллов Директа,
  «developer token не одобрен» и т. п. Ошибка одного источника **не ломает** анализ другого.
- Коды ответов: `409` — предложение устарело, `429` — лимит (можно повторить позже), `502` — API отклонил изменение,
  `401` — нужен ключ доступа `X-API-Key`.

## 7. API (кратко)

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/health` | проверка подключений к кабинетам |
| GET/PUT | `/api/settings` | целевые KPI (CPA, CTR, дневной бюджет, допуски) |
| POST | `/api/analyze` | анализ + список рекомендаций |
| POST | `/api/recommendations/{id}/confirm` | применить изменения (тело: `{"confirmed_by": "Имя"}`) |
| POST | `/api/recommendations/{id}/reject` | отклонить |
| GET | `/api/journal`, `/api/journal.csv` | журнал |

Документация Swagger: `/docs`.

## 9. Безопасность

- Секретов в коде нет: только переменные окружения.
- Приложение по умолчанию слушает `127.0.0.1` — не выставляйте в интернет без HTTPS и `API_KEY`
  (лучше — за обратным прокси с авторизацией и ограничением по IP).
- Папку `backend/data/` (настройки и журнал) не публикуйте.

## Вкладка «Токены» (самый простой способ подключить аккаунты)

В приложении есть отдельная вкладка **Токены** — там не нужно ничего редактировать руками.

1. Запустите приложение и откройте `http://127.0.0.1:8000`.
2. Слева нажмите **Токены**.
3. В блоке «Яндекс Директ» вставьте OAuth-токен, нажмите **Сохранить Яндекс Директ**.
4. В блоке «Google Ads» заполните Developer token, Client ID, Client secret, Refresh token и номер рекламного аккаунта, нажмите **Сохранить Google Ads**.
5. Нажмите **Проверить подключение** — приложение обратится к API только за служебной информацией (ставки, бюджеты и кампании не меняются) и покажет по каждому сервису «работает» или причину ошибки по-русски.

Что важно:

* Значения сохраняются **только на этом компьютере**, в служебной папке приложения (файл `credentials.json` в папке данных, права 600), и никуда не отправляются.
* Уже сохранённый токен виден в виде подсказки (`y0_A••••••3456`) — вставить его повторно не нужно. Чтобы заменить, вставьте новое значение; чтобы удалить — поставьте галочку «удалить сохранённое значение» и сохраните.
* Пустое поле означает «не менять» — случайно стереть токен нельзя.
* Если вместо токена вставить фразу с пробелами или слишком короткий текст, приложение вежливо откажет с пояснением.
* Значения из `.env` тоже работают: сохранённое в интерфейсе имеет приоритет над файлом.
* Признак готовности: рядом с названием сервиса появляется зелёная метка «заполнено».

## Вкладка «Метрика и запуски»

Показывает, что происходит на сайте: сколько людей заходит и сколько скачивают демо.

**Яндекс Метрика** — на вкладке «Токены» в блоке «Яндекс Метрика» укажите номер счётчика (тот же OAuth-токен Директа подходит и для Метрики). Что появится:

* визиты, посетители, просмотры, процент отказов;
* график визитов по дням и источники переходов (поиск / реклама / прямые заходы);
* достижения целей, в том числе «скачивание демо» (если имя цели содержит «скач» или «download», оно считается скачиванием).

**Журнал сервера** — скачивания файлов программы прямо из лога сайта. В блоке «Журнал сервера» укажите путь к access-логу (на хостинге SprintHost это файл вида `.../domains/evgeniymamonov.com/logs/access.log`). Что появится:

* сколько всего скачали, сколько сегодня и вчера, сколько уникальных адресов;
* по каким часам чаще скачивают (удобно для расписания рекламы);
* какие файлы популярнее (Кадрик / Экранник / Диктик — видно отдельно);
* последние 50 запусков с датой, файлом, IP и размером + выгрузка в CSV.

Роботы (Googlebot, YandexBot и подобные) и запросы с ошибками отбрасываются, чтобы цифры не завышались. Файл читается только на чтение, в него ничего не записывается.
